# The Board Digest

ต้นแบบภาษาไทยสำหรับทีม Company Secretary ใช้ข้อมูลประชุมจำลองและบันทึกข้อมูลกับไฟล์ใน SQLite บนเครื่อง

## เปิดแอป

เปิด Terminal ในโฟลเดอร์นี้แล้วใช้ Node.js 24 ขึ้นไป

```powershell
node server.mjs
```

เปิด [The Board Digest](http://127.0.0.1:8765/) ในเบราว์เซอร์ ข้อมูลจะอยู่ที่ `data/board.sqlite` ตามค่าเริ่มต้น กำหนดตำแหน่งอื่นได้ผ่านตัวแปร `BOARD_DIGEST_DATA` กด Ctrl+C เพื่อหยุดเซิร์ฟเวอร์

## ทำคำบรรยายวาระจาก PowerPoint

1. สลับเป็นฝ่ายเจ้าของวาระ เปิดนัดและวาระของตน แล้วเลือก **ทำคำบรรยายจาก PowerPoint**
2. อัปโหลดไฟล์ `.pptx` ไม่เกิน 20 MB และ 100 สไลด์ หรือให้ระบบอ่านไฟล์ `.pptx` ที่แนบไว้แล้ว
3. เปิดข้อความต้นฉบับของแต่ละสไลด์ เลือกสไลด์ที่จะใช้ แก้ประเด็นหลักและคำสำคัญตามหลักฐาน แล้วกด **ยืนยันประเด็นที่เลือก**
4. กด **สร้างร่างคำบรรยาย** ตรวจข้อความและเลขสไลด์อ้างอิง แล้วกด **ดาวน์โหลด Word (.docx)** หากยืนยันประเด็นอีกครั้ง ระบบจะให้สร้างร่างจากข้อมูลที่ยืนยันล่าสุด

การแปลงทำในเครื่องด้วย Python 3 และใช้เฉพาะข้อความที่อ่านได้จากกล่องข้อความและตารางในสไลด์ ภาพ กราฟ และบันทึกผู้บรรยายอยู่นอกขอบเขตการดึงข้อความ ร่างใช้ถ้อยคำที่เจ้าของวาระยืนยัน หากรันนอก Codex และระบบหา Python ไม่พบ ให้ตั้ง `BOARD_DIGEST_PYTHON` เป็นพาธของ Python 3

## เดินงานด้วยนัดตัวอย่าง

1. ใช้บทบาท **ComSec** แล้วเปิดนัด **คณะกรรมการบริษัท** วันที่ 10 ก.พ. 2027 ตรวจว่าเอกสารงบประมาณมีสองฉบับและเลือกฉบับที่ตรวจรับแล้วสำหรับใช้ประชุม
2. เปิด **การแจ้งเตือน** ใช้เวลาจำลอง 7 ก.พ. 2027 เวลา 09:00 น. แล้วรันซ้ำ ครั้งแรกประมวลผลหนึ่งรายการและครั้งที่สองประมวลผลศูนย์รายการ
3. เปิดนัดเดิมและบันทึกการจัดประชุม เลือก **จำลองร่างจาก transcript** แล้วเปิดวาระงบประมาณเพื่อตรวจจุดรอยืนยันและช่วงเวลาอ้างอิง
4. บันทึกร่างวาระ ส่งให้ตรวจ รับรอง แล้วเผยแพร่ สร้างงานติดตามจากฉบับที่รับรองและมอบหมายให้ฝ่ายการเงิน
5. สลับเป็น **ฝ่ายการเงิน** แล้วเปิด **งานติดตาม** ระบุหลักฐานและส่งให้ตรวจ สลับกลับเป็น **ComSec** เพื่อตรวจและปิดงาน

## รันทดสอบ

```powershell
node check.mjs
```

ชุดตรวจเรียก HTTP API ด้วยฐานข้อมูลชั่วคราวและครอบคลุม AC-01 ถึง AC-08 รวมทั้งการเปิดข้อมูลและไฟล์เดิมหลังรีสตาร์ต เซิร์ฟเวอร์ส่งสถานะล่าสุดผ่าน API และหน้าจอตรวจข้อมูลทุก 30 วินาที โดยรักษาข้อมูลในฟอร์มระหว่างแก้ไข

การเลือกบทบาทเป็นส่วนหนึ่งของเดโม การร่างรายงานอาศัยข้อความ transcript ที่มีอยู่ และการแจ้งเตือน T−3 รันจากหน้าทดลอง ต้นแบบนี้ออกแบบสำหรับข้อมูลจำลองบนเครื่อง
